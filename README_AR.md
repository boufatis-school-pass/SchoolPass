# SchoolPass 3.0.0 — الإصدار الرئيسي الجديد

**نظام إدارة رخص دخول التلاميذ وخروجهم الاستثنائي والتقارير الإدارية**  
**المؤسسة:** ثانوية المجاهد بسجراري لخضر بوفاطيس  
**المنصة المستهدفة:** Windows 10/11، 64-bit.

## الجديد في 3.0.0

- إعادة تنظيم التجربة البصرية باستخدام محرك سمات حديث مبني على ttkbootstrap 2.2.6 مع الإبقاء على عناصر Tk/ttk القياسية ومنطق الأعمال الحالي.
- واجهة SchoolPass موحدة بخيارات نهارية وليلية، ألوان مؤسسية، تباين أوضح، بطاقات معلومات ومسافات وخطوط محسنة.
- نوافذ منبثقة عربية موحدة بدل مسار MessageBox الأصلي، مع اتجاه RTL ومحاذاة عربية وأزرار مفهومة ونتائج متوافقة مع وظائف التأكيد.
- إضافة تقرير إحصائي شامل PDF يتضمن المؤشرات اليومية والأسبوعية والشهرية، العمليات حسب الأقسام والمشرفين، أسباب العمليات، فترات الغياب، الإلغاءات، وحالات الطرد حسب الأستاذ.
- إضافة ملف تاريخي قابل للحفظ والطباعة من ملف التلميذ الشامل، مع المحافظة على خصوصية رقم هوية ولي الأمر.
- إضافة «إنشاء وطباعة التقرير» لتقرير حالات الطرد حسب الأستاذ، وإدخال التقارير المُنشأة عبر سجل العمليات والتقرير الشهري في مسار معاينة/طباعة موحد.
- توحيد إجراءات إنشاء PDF ومعاينته والإرسال إلى الطابعة المختارة، مع بقاء خيار حفظ ملف التقرير.
- تقوية بوابة الإطلاق والبناء: فحص صياغة سكريبت PowerShell الفرعي قبل تشغيله، وفحص ترميز BOM لسكريبتات Windows PowerShell 5.1، وتجميع أصول ttkbootstrap/Pillow ضمن PyInstaller.

## عرض اللغة العربية
تُعرض النصوص الثابتة والديناميكية في عناصر الواجهة والجداول والقوائم المنسدلة والرسوم البيانية والنوافذ المخصصة عبر طبقة موحدة لتشكيل العربية واتجاهها. وتبقى القيم المنطقية الأصلية هي التي تُحفظ وتُستخدم في البحث والفرز؛ لا تُخزّن الحروف المرئية المشكلة بدل النص العربي الأصلي. كما تُعالج تقارير PDF من خلال محرك تشكيل مستقل.

حقول الكتابة لا يُعاد تشكيل نصها أثناء كل ضغطة مفتاح، حتى لا يتضرر موضع المؤشر أو التحرير أو النص المحفوظ. لذلك يجب فحص الكتابة العربية داخل حقول الإدخال على جهاز Windows المستهدف، إلى جانب فحص الواجهة والجداول والنوافذ والطباعة. لا يُعد اختبار الواجهة الوهمي بديلًا عن الفحص المرئي على Windows.

## الوظائف الأساسية المحفوظة

- إدارة التلاميذ واستيراد Excel/CSV مع الحفاظ على السجلات السابقة عند تحديث القائمة.
- رخصة الدخول للتأخر والعودة بعد الغياب، مع عدم احتساب يوم العودة ضمن مدة الغياب.
- اشتراط حضور الولي عند تجاوز الغياب يومين وفق قواعد التبرير القائمة.
- رخصة الخروج الاستثنائي بنسختين: للحاجب وللتلميذ، مع تسجيل العودة.
- تسجيل الطرد من الحصة مع اسم الأستاذ والمادة، والتواجد في الإدارة كنوع مستقل.
- سجل عمليات، ملف تاريخي للتلميذ، بحث وفلاتر وتصدير CSV وتقارير PDF.
- لوحة تحكم وإحصائيات يومية وأسبوعية وشهرية وتنبيهات الخروج المفتوح.
- حساب مدير ومشرفين، صلاحيات وسجل تدقيق ونسخ احتياطي واستعادة.
- رخص A6، ورخصتان على ورقة A4، وتقارير A4 أفقية متعددة الصفحات.
- تحديث داخلي يتحقق من SHA-256 قبل فتح المثبّت للتحديث.

## البيانات والتوافق

لا يغيّر الإصدار 3.0.0 مخطط قاعدة البيانات (يبقى schema version 6)؛ التغييرات الرئيسية في الواجهة والتقارير والبناء. تبقى قاعدة البيانات في:

`%LOCALAPPDATA%\SchoolPass\schoolpass.sqlite3`

التحديث لا يحذف قاعدة البيانات ولا يستبدلها. أنشئ نسخة احتياطية من داخل البرنامج قبل تحديث النسخة الميدانية. حماية DPAPI لأرقام هويات الأولياء مرتبطة بحساب Windows الذي أنشأها؛ لا تنقل قاعدة البيانات إلى حساب أو جهاز آخر دون خطة نقل مناسبة.

لا تُرفع قاعدة البيانات أو قوائم التلاميذ الحقيقية أو النسخ الاحتياطية أو التقارير إلى GitHub.

## المستودع والبناء

المستودع الحالي:

`https://github.com/boufatis-school-pass/SchoolPass`

ارفع محتويات الحزمة إلى جذر المستودع الحالي (وليس ملف ZIP نفسه)، مع الحفاظ على مجلد `.github/workflows`. بعد مراجعة الملفات، أنشئ وادفع وسم الإصدار:

```powershell
git tag v3.0.0
git push origin v3.0.0
```

عند دفع الوسم، ينفذ GitHub Actions فحوص المصدر والاختبارات ثم يبني نسخة Windows x64 ويُنشئ `SchoolPass_Setup.exe` وملف SHA-256 وينشرهما في GitHub Releases. لم يُنفذ النشر إلى GitHub من بيئة إعداد هذه الحزمة، لذلك لا تدّعي هذه الحزمة أن ملف المثبّت النهائي قد بُني أو نُشر.

## حدود الاختبار

يجب اجتياز الاختبارات الآلية قبل البناء. لكن اعتماد الإصدار الميداني يتطلب أيضًا تجربة فعلية على Windows 10/11، بما في ذلك شكل الواجهة والنوافذ العربية، التثبيت فوق الإصدار 2.5.3 مع التحقق من بقاء البيانات، الطباعة الفعلية على Canon LBP6000B، وتجربة جميع أنواع التقارير. يجب عدم الاعتماد على نجاح اختبارات المصدر وحدها كبديل عن هذه التجربة.
