# SchoolPass 2.5.4 — المستودع الرسمي

**نظام إدارة رخص دخول التلاميذ وخروجهم الاستثنائي**  
**المؤسسة:** ثانوية المجاهد بسجراري لخضر بوفاطيس  
**المنصة المستهدفة:** Windows 10/11، 64-bit.

هذا المجلد هو مصدر الإصدار 2.5.4 فقط، ومهيأ للرفع إلى جذر مستودع GitHub. لا يتضمن قواعد بيانات المؤسسة أو نسخًا تنفيذية قديمة أو مجلدات بناء مؤقتة.

## الوظائف الأساسية

- إدارة التلاميذ واستيراد Excel/CSV مع الحفاظ على السجلات السابقة عند تحديث القائمة.
- رخصة الدخول للتأخر والعودة بعد الغياب، مع تطبيق قاعدة عدم احتساب يوم العودة ضمن مدة الغياب.
- اشتراط حضور الولي شخصيًا عند تجاوز الغياب يومين، حتى عند وجود شهادة طبية.
- رخصة الخروج الاستثنائي بنسختين: للحاجب وللتلميذ، مع تسجيل العودة.
- سجل عمليات، ملف تاريخي للتلميذ، بحث وفلاتر وتصدير.
- لوحة تحكم وإحصائيات يومية وأسبوعية وشهرية وتنبيهات الخروج المفتوح.
- حساب مدير ومشرفين، صلاحيات وسجل تدقيق ونسخ احتياطي واستعادة.
- رخصتان مختلفتان على ورقة A4 عمودية، مع المحافظة على تصميم رخصة الخروج المعتمد.
- تقرير يومي تفصيلي للمدير بصيغة A4 أفقية، كل رخصة في سطر مستقل، مع بداية الغياب وطريقة التبرير وبيانات الولي المتاحة ورقم الهوية كاملًا. لا يمكن فتح هذا التقرير إلا لحساب المدير.
- مظهر ليلي ونهاري، واجهة متكيفة مع عرض الشاشة، تمرير بعجلة الماوس، وتحسينات عرض العربية، وتحديث داخلي ينزّل المثبّت ويتحقق من SHA-256 قبل التثبيت.

## محتويات المستودع

- `app.py`: واجهة Windows.
- `schoolpass_core.py`: منطق البرنامج وقاعدة البيانات والصلاحيات والطباعة والتقارير.
- `requirements.txt`: مكتبات التشغيل.
- `requirements_dev.txt`: متطلبات البناء والاختبار.
- `SchoolPass_Setup.iss`: إعدادات مثبّت Inno Setup.
- `build_windows.ps1`: بناء البرنامج كاملًا على Windows.
- `build_installer_only.ps1` و`build_installer_only.bat`: إنشاء المثبّت من النسخة المحمولة الموجودة دون حذفها أو إعادة بنائها.
- `.github/workflows/release-windows.yml`: بناء مثبّت Windows ونشره تلقائيًا عند دفع وسم إصدار يبدأ بـ `v`.
- ملفات الاختبارات والفحص المسبق.
- دليل الاستخدام وقالب CSV.

## قاعدة البيانات والخصوصية

تُخزّن قاعدة البيانات محليًا خارج مجلد تثبيت البرنامج في:

`%LOCALAPPDATA%\SchoolPass\schoolpass.sqlite3`

لا يتضمن المثبّت تعليمات حذف قاعدة البيانات أو استبدالها. التحديث يعيد ملفات البرنامج فقط. ومع ذلك، أنشئ نسخة احتياطية قبل أي تحديث أو استعادة.

أرقام هويات الأولياء تُحفظ مشفرة باستخدام Windows DPAPI، ولا يظهر الرقم الكامل في الرخصة المطبوعة. يمكن للمدير فقط إنشاء التقرير اليومي الذي يعرض الرقم كاملًا؛ لذلك يجب حفظ ملفات التقرير وتداولها ضمن الإدارة وبالقدر الضروري فقط.

ملفات النسخ الاحتياطية ليست مشفرة بالكامل بواسطة التطبيق. استخدم BitLocker أو وسيطًا محميًا، ولا ترفع قاعدة البيانات أو ملفات النسخ أو التقارير إلى GitHub.

**مهم عند نقل البيانات:** حماية DPAPI مرتبطة بحساب Windows الذي أنشأ البيانات. لا تفترض أن نقل قاعدة البيانات إلى حاسوب أو حساب Windows مختلف سيتيح فك تشفير أرقام الهوية القديمة.

## تحديث مستودع GitHub الحالي

المستودع المعتمد لهذا المشروع موجود بالفعل:

`https://github.com/boufatis-school-pass/SchoolPass`

لا تنشئ مستودعًا جديدًا. فك ضغط حزمة المصدر، ثم ارفع **محتوياتها** إلى جذر المستودع الحالي مع الحفاظ على المجلدات المخفية، خصوصًا `.github/workflows`. يمكن تنفيذ ذلك عبر Git بعد استنساخ المستودع أو عبر واجهة GitHub لرفع الملفات. راجع الملفات المعدلة قبل اعتمادها، ولا ترفع قواعد بيانات أو قوائم تلاميذ حقيقية أو تقارير أو نسخًا احتياطية.

إذا كان المستودع عامًا، يستطيع فاحص التحديثات قراءة صفحة Releases عبر واجهة GitHub العامة. بعد رفع المصدر إلى الفرع الرئيسي، أنشئ وادفع الوسم `v2.5.4` لتشغيل سير بناء Windows. لا تضع ملف ZIP داخل المستودع؛ ارفع محتوياته إلى الجذر.

## نشر إصدار وتحديث البرنامج من داخله

عند اعتماد تحديث جديد:

1. حدّث رقم الإصدار في الملفات الثلاثة: `schoolpass_core.py` و`VERSION.txt` و`SchoolPass_Setup.iss`.
2. اكتب التغييرات في `ملاحظات_الإصدار.md`.
3. أرسل التغييرات إلى GitHub.
4. أنشئ وادفع وسمًا مطابقًا للإصدار، مثل `v2.5.4` للإصدار الحالي:

```bash
git tag v2.5.4
git push origin v2.5.4
```

5. يبدأ GitHub Actions بناء نسخة Windows وتشغيل الاختبارات، ثم ينشر `SchoolPass_Setup.exe` وملف SHA-256 في GitHub Releases.
6. من SchoolPass اضغط «بحث عن تحديثات». إذا وجد إصدارًا أحدث، يتحقق من وجود ملف المثبّت قبل فتح صفحة الإصدار.
7. نزّل المثبّت من GitHub وشغّله فوق النسخة الحالية. لا تحذف مجلد `%LOCALAPPDATA%\SchoolPass`.

زر البحث لا يثبت التحديث بصمت؛ يعرض التحديث ثم يفتح صفحة الإصدار حتى يراجع المدير ملاحظاته وينزّل المثبّت بنفسه.

## بناء البرنامج محليًا على Windows

المتطلبات: Windows 10/11 64-bit واتصال إنترنت في البناء الأول.

1. فك ضغط المشروع كاملًا في مجلد عادي، وليس داخل ملف ZIP.
2. شغّل `ابدأ_هنا.bat`.
3. يفحص السكربت Python 64-bit والمكتبات وتشكيل العربية والخط، ثم يشغّل الاختبارات.
4. يبني PyInstaller النسخة المحمولة في `dist\SchoolPass`.
5. ينشئ المثبّت `dist\SchoolPass_Setup.exe` ويتحقق من وجوده وحجمه وترويسة Windows EXE.
6. لا تظهر رسالة نجاح إلا بعد نجاح مرحلة المثبّت والتحقق من الملف الناتج.

إذا كانت النسخة المحمولة موجودة بالفعل وفشل المثبّت، شغّل `build_installer_only.bat`. هذه الأداة لا تحذف `dist` ولا تعيد بناء النسخة المحمولة؛ بل تعيد محاولة إنشاء المثبّت فقط.

## الاختبارات وحدود الاعتماد

أُجريت اختبارات Python وفحص ترميز UTF-8 ومراجعة نقاط حساسة في التقرير اليومي وفاحص التحديثات. لكن بناء EXE والمثبّت واختبار واجهة Windows والطباعة على Canon LBP6000B يتطلب تشغيل حزمة البناء على Windows وتجربة فعلية في المؤسسة.

**لا تعتمد قاعدة البيانات الأصلية لأول اختبار.** ابدأ بنسخة احتياطية تجريبية، ثم اختبر الدخول والخروج والتقرير والطباعة والاستعادة قبل تعميم التحديث.
