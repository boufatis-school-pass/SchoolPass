# إعداد Cloudflare Bridge — SchoolPass 4.9.3

هذا الدليل ينشر خدمة التحقق وطلبات عودة التلميذ عبر الإنترنت. قاعدة D1 المستخدمة في إعداد المشروع اسمها `schoolpass-cloud`، وارتباطها موجود في `wrangler.toml` تحت اسم `DB`.

**تنبيه بخصوص معرّف قاعدة البيانات:** ملف `wrangler.toml` يحتوي حاليًا على قيمة مؤقتة `REPLACE_WITH_D1_DATABASE_UUID`. افتح قاعدة `schoolpass-cloud` في لوحة Cloudflare، وانسخ حقل Database ID / UUID كما يظهر تمامًا، ثم استبدل القيمة المؤقتة به. معرّف D1 UUID يكون بالشكل المعتاد `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` (36 محرفًا مع الشرطات). لا تستخدم Account ID أو أي رمز طويل آخر.

## 1. إنشاء Worker

1. افتح لوحة Cloudflare ثم **Workers & Pages**.
2. اختر **Create application** ثم **Create Worker**.
3. استخدم الاسم `schoolpass-cloud-bridge`.
4. افتح **Edit code** واستبدل محتوى الملف بالمحتوى الكامل الموجود في المستودع: `cloudflare/worker.js`.
5. اضغط **Deploy**. سيظهر عنوان عام ينتهي عادةً بـ `.workers.dev`.

## 2. ربط قاعدة D1

من إعدادات Worker افتح **Bindings** ثم **Add binding → D1 database**. أدخل القيم التالية حرفيًا:

- Variable name: `DB`
- D1 database: `schoolpass-cloud`

إذا أردت استخدام Wrangler بدل لوحة التحكم، لا تنفذ أوامر النشر قبل وضع UUID الصحيح داخل `cloudflare/wrangler.toml`.

احفظ الإعدادات وأعد نشر Worker. ثم افتح قاعدة D1 من **Storage & databases → D1 SQL Database**، وافتح **Console**، ونفّذ محتوى الملف `cloudflare/schema.sql` مرة واحدة. ينشئ ذلك جداول الرخص والطلبات وحدود المحاولات، ويمنع وجود أكثر من طلب عودة معلّق للرخصة نفسها.

## 3. اختبار عنوان الخدمة

افتح في المتصفح:

`https://عنوان-worker.workers.dev/health`

يجب أن تظهر استجابة JSON فيها `"ok":true` و`"database":true`. إذا ظهرت `d1_not_ready` فتأكد من ربط قاعدة D1 باسم `DB` ومن تنفيذ ملف الجداول. حقل `device_auth_configured` يكون `false` قبل إضافة السر في الخطوة الرابعة، ثم يجب أن يصبح `true` بعده.

## 4. إضافة المفتاح السري بعد تثبيت SchoolPass 4.9.3

1. افتح SchoolPass 4.9.3 على حاسوب المؤسسة، ثم **إعدادات المؤسسة**.
2. ضع عنوان Worker الكامل في حقل Cloudflare، مثل `https://schoolpass-cloud-bridge.example.workers.dev`.
3. اضغط **إنشاء / تجديد مفتاح الربط السري**. سيُحفظ المفتاح مشفّرًا بواسطة Windows DPAPI ويُنسخ إلى الحافظة.
4. في إعدادات Worker افتح **Settings → Variables and Secrets → Add → Secret**.
5. الاسم: `DEVICE_API_KEY`. القيمة: الصق المفتاح الذي أنشأه SchoolPass، ثم احفظ وأعد النشر.
6. ارجع إلى SchoolPass واضغط **حفظ الإعدادات**.

لا تضع قيمة المفتاح في GitHub أو ملف نصي أو محادثة. المفتاح لا يُخزّن في مصدر البرنامج، ويُحفظ في قاعدة بيانات SchoolPass محليًا بتشفير Windows DPAPI. يجب إنشاء مفتاح منفصل على كل حاسوب يُستخدم كجهاز مؤسسي، أو اعتماد نفس مفتاح الجهاز عند تشغيل نسخة احتياطية من نفس ملف بيانات Windows.

## 5. سلوك النظام

- QR الجديد يفتح صفحة HTTPS عامة تعرض رقم الرخصة ونوعها واسم التلميذ والقسم ووقت الإصدار فقط.
- رموز QR التي طُبعت قبل ضبط رابط Cloudflare تحتفظ بعنوانها المحلي القديم؛ أعد طباعة الرخصة بعد ضبط الخدمة ليُنشأ رمز جديد يشير إلى صفحة HTTPS العامة.
- رخص الدخول تنتهي بعد ساعتين. تبقى بياناتها التاريخية محفوظة ولا تُحذف.
- رخصة الخروج الاستثنائي لا تنتهي بمرور ساعتين؛ تبقى مفتوحة إلى أن تسجل العودة.
- مسح QR لا يسجّل العودة. يضغط الحاجب «طلب تسجيل عودة التلميذ»، فيصل الطلب إلى Cloudflare.
- يستطلع SchoolPass الطلبات كل 15 ثانية تقريبًا. تظهر للمشرف نافذة فيها اسم التلميذ والقسم ووقت الخروج واسم الولي ووقت الطلب.
- لا يتغير السجل المحلي إلا بعد تأكيد مشرف داخل البرنامج. بعد التأكيد يُنشأ سجل دخول مرتبط بالرخصة الأصلية.
- إذا كان البرنامج مغلقًا أو الحاسوب غير متصل، يحتفظ Worker بالطلب المعلّق. عند إعادة تشغيل البرنامج وعودة الإنترنت تتم مزامنته.
- لا ترسل قاعدة D1 رقم بطاقة الولي أو رقم هاتفه أو أي حقل هوية. اسم الولي يُقرأ محليًا عند عرض طلب العودة فقط.

## 6. نشر بديل باستخدام Wrangler

يمكن تنفيذ النشر من مجلد المستودع:

```powershell
npm install --global wrangler
npx wrangler login
npx wrangler d1 migrations apply schoolpass-cloud --remote --config cloudflare/wrangler.toml
npx wrangler deploy --config cloudflare/wrangler.toml
npx wrangler secret put DEVICE_API_KEY --name schoolpass-cloud-bridge
```

عند طلب المفتاح في الطرفية، الصق القيمة التي أنشأها SchoolPass. لا تمرّرها كوسيط أمر حتى لا تظهر في سجل الأوامر.

## ملاحظة مهمة

وجود Database ID في إعداد المشروع لا ينشر Worker تلقائيًا في حساب Cloudflare. لا بد من تنفيذ خطوات النشر والربط والسر أعلاه داخل حسابك. لا تستخدم صفحة QR عبر الإنترنت مع التلاميذ قبل نجاح `/health` والتأكد من ربط D1 وإضافة سر الجهاز.
